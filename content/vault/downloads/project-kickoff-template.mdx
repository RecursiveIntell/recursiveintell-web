## Overview

Before writing code, get alignment. This template forces clarity on what you're building, why, and how you'll know it worked. Fill it out in 30 minutes; save weeks of confusion later.

## The Template

### Project Overview

```markdown
# Project: [Name]

**One-sentence summary:**
[What are we building and why?]

**Owner:** @name
**Team:** @name, @name, @name
**Target Date:** YYYY-MM-DD
**Status:** Planning / In Progress / Blocked / Complete
```

### Problem Statement

```markdown
## Problem

**What problem are we solving?**
[Describe the pain point or opportunity]

**Who has this problem?**
[User segment, persona, or team]

**How do we know it's a problem?**
[Data, user research, or anecdotes]

**What happens if we don't solve it?**
[Stakes and consequences]
```

### Solution

```markdown
## Solution

**What are we building?**
[Description of the solution]

**How does it solve the problem?**
[Connection between solution and problem]

**What are we NOT building?**
[Explicit scope boundaries]
```

### Success Criteria

```markdown
## Success Criteria

**How will we know this worked?**

| Metric | Current | Target | How Measured |
|--------|---------|--------|--------------|
| [e.g., Error rate] | 5% | <1% | Datadog dashboard |
| [e.g., User satisfaction] | 3.2/5 | 4.0/5 | Survey |

**Definition of Done:**
- [ ] [Specific deliverable or capability]
- [ ] [Specific deliverable or capability]
- [ ] [Specific deliverable or capability]
```

### Risks & Mitigations

```markdown
## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| [Description] | High/Med/Low | High/Med/Low | [What we'll do] |
```

### Dependencies

```markdown
## Dependencies

**What do we need from others?**
- [Team/person]: [What we need] by [Date]

**Who depends on us?**
- [Team/person]: [What they need] by [Date]
```

### Milestones

```markdown
## Milestones

| Milestone | Description | Target Date |
|-----------|-------------|-------------|
| M0 | Kickoff complete, team aligned | [Date] |
| M1 | [First meaningful deliverable] | [Date] |
| M2 | [Second deliverable] | [Date] |
| M3 | Launch / complete | [Date] |
```

### Open Questions

```markdown
## Open Questions

- [ ] [Question that needs answering before/during work]
- [ ] [Question that needs answering before/during work]
```

## How to Use

1. Fill out before the first team meeting
2. Review with stakeholders for alignment
3. Update as you learn (it's a living doc)
4. Reference during standups and check-ins
5. Archive with final outcomes for future reference

## Tips

- If you can't fill out "Problem," you're not ready to start
- "What are we NOT building" prevents scope creep
- Fewer milestones are better—3-4 max
- Review success criteria weekly during the project
